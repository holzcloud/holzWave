# Test plan

Seven parts: how to run everything locally, the per-platform manual list for hardware the owner owns, the record of the
macOS acceptance of Phase 2, the Windows and Linux list of Phase 2.2 (Part 4), connections (Part 5), files and previews
with the extras (Part 6), and the AI chat with the Apple on-device model and the rest of the extras (Part 7). All of it
runs locally; nothing here needs GitHub (D-04).

## Part 1: run everything locally

```sh
. scripts/env.sh                      # Rust stable and Zig 0.16 on PATH (the pinned engine needs exactly 0.16)
npm --prefix app ci                   # once: typescript, the Tauri CLI and playwright-core, nothing else
(cd app && npx playwright-core install webkit chromium)   # once: the two browsers of the browser tests, cached

cargo test --workspace --offline      # core, app shell (headless, real shells), the project policy, the spike
npm test --prefix app                 # builds app/dist with tsc, then the node unit tests
npm run test:browser --prefix app     # WebKit and Chromium against app/dist with an in-page Tauri stub

cargo test --release -p holzwave-core --offline --test budget -- --ignored --nocapture   # the budgets
npm run bench:build --prefix app      # builds app/dist-bench/index.html, the renderer benchmark (open it in a browser)
cargo run -p holzwave-app             # the app itself, for the lists below
```

From the Mac, without a Windows or Linux machine (these prove that the code compiles and that the Unix half passes on
Linux; they do not replace Part 4):

```sh
sh scripts/cross-check.sh all                 # cargo check of every test target for Windows (GNU ABI) and Linux; app for Windows
sh scripts/linux-container-test.sh all        # core and app tests in an Ubuntu container (Docker): core, app or all
sh scripts/linux-container-bundle.sh          # deb and rpm built and inspected in the container, AppImage tried
sh scripts/nextcloud-live-test.sh             # a real Nextcloud in Docker and a TLS proxy; needs Docker and about 1 GB once
```

Each prints `ok` as its last line and exits non-zero otherwise. The container is arm64 on an Apple Silicon Mac: a proxy
for structure and tests, not for graphics. On Windows and Linux machines the same build is described in
[build-windows.md](build-windows.md) and [build-linux.md](build-linux.md).

The AI chat adds checks that the default run does not cover. The first block needs no Zig, no Xcode and no network, the
second prints numbers and runs on release builds (three runs each), and the third spends tokens or needs a real server and
is run by hand. The ignored tests are named in the files they live in; every one reads its settings from environment
variables and never from a file.

```sh
# the quick set: no Zig, no Xcode, no network
cargo test --locked --offline -p holzwave-core --no-default-features --lib ai::               # the AI core
cargo test --locked --offline -p holzwave-core --no-default-features --test project_policy    # the policy and the guards of the documents
cargo test --locked --offline -p holzwave-ipc -p wsh                                          # the socket, `wsh ai`, the real binary
cargo test --locked --offline -p holzwave-apple-ai                                            # the Apple crate with a scripted backend
node docs/design/render.cjs --check                                                           # every drawn view renders

# numbers, release builds: cancel latency, time to first delta, cost per event, read-text budget, agent suite
cargo test --release --locked --offline -p holzwave-core --no-default-features --test ai_http -- --nocapture a_cancel_closes_the_socket_within_250_ms
cargo test --release --locked --offline -p holzwave-core --no-default-features --test ai_matrix_budget -- --ignored --nocapture
cargo test --release --locked --offline -p holzwave-core --no-default-features --test ai_tls -- --ignored --nocapture time_to_first_delta_and_cost_per_event
cargo test --release --locked --offline -p holzwave-core --test ai_readtext -- --ignored --nocapture a_read_of_the_whole_budget_is_cut_flagged_and_fast
cargo test --locked --offline -p holzwave-core --no-default-features --test ai_agent          # three runs in a row

# live checks with throwaway keys that have a small spending limit (a key goes into the environment and nowhere else)
HOLZWAVE_LIVE_ANTHROPIC_KEY=<key> cargo test --locked -p holzwave-core --no-default-features --test ai_wire_anthropic -- --ignored --nocapture live_contract_check_against_the_real_service
HOLZWAVE_TEST_GEMINI_KEY=<key> cargo test --locked -p holzwave-core --no-default-features --test ai_wire_gemini -- --ignored --nocapture live_text_and_tool_turn_against_the_real_service
HOLZWAVE_TEST_HTTPS_URL=<https url> cargo test --locked -p holzwave-core --no-default-features --test ai_tls -- --ignored --nocapture real_https_request_with_the_platform_verifier
HOLZWAVE_TEST_SSH_HOST=<host> HOLZWAVE_TEST_SSH_USER=<user> HOLZWAVE_TEST_SSH_KEY=<key file> HOLZWAVE_TEST_SSH_KNOWN_HOSTS=<known_hosts file> \
  cargo test --locked --offline -p holzwave-core --no-default-features --lib exec_against_a_real_host -- --ignored --nocapture
HOLZWAVE_TEST_APPLE=1 cargo test --locked --offline -p holzwave-apple-ai --test live -- --ignored --nocapture   # macOS 26, Apple Intelligence on
sh scripts/cross-check.sh all                 # Windows (GNU ABI) and Linux compile of every test target, from the Mac
```

Optional variables: `HOLZWAVE_LIVE_ANTHROPIC_MODEL` and `HOLZWAVE_TEST_GEMINI_MODEL` name another model,
`HOLZWAVE_TEST_BAD_CERT_URL` is an https address with a bad certificate that must be refused, and
`HOLZWAVE_TEST_SSH_PORT` is the port of the real SSH server. Part 7 says what to record from each run.

Notes:

- `npm run test:browser` takes `--only <part of a file name>` and `--engine webkit|chromium`; a test fails on any page
  error or Content-Security-Policy violation, even when its own assertions passed.
- The budget tests are `#[ignore]` because a debug build is meant to be slower than the budget. They print the measured
  update plus encode time and the key-to-frame time; the numbers of 2026-10-11 are in
  [architecture.md](architecture.md) section 12. They are measured without the webview.
- The dev profile builds `libghostty` in Zig debug mode and is slow on very large feeds; use `--release` for anything
  that moves megabytes.
- `UPDATE_FIXTURES=1 cargo test --offline` rewrites the two golden files (`app/tests/fixtures/frames.json` and
  `protocol.json`); review the diff before committing it.
- `core/tests/project_policy.rs` is part of `cargo test --workspace`. It fails when a dependency, a network API, a remote
  origin or a CI workflow appears (DESK-26, D-03, D-04), and when [config.md](config.md) no longer matches the loaders.
- `core/tests/project_policy.rs` also holds the documents: it fails when a row of Part 7 is missing or twice in this file,
  when a public file names a plan of the private planning tree, when a document holds a hidden or control character, when
  [architecture.md](architecture.md) section 6 states other command and event counts than the protocol golden or leaves out
  an AI command or event, and when a document names a test target that does not exist.
- A key goes into an environment variable of the live tests and nowhere else: not into a file, and not into a command
  line that your shell history keeps (put a space before the line, or read the key from the keychain into the variable).
- The live tests spend tokens: use throwaway keys with a small spending limit, and revoke them afterwards. They are
  `#[ignore]`d and do nothing without their variables.
- The engine, the shell crate and the goldens need Zig 0.16; the real Apple model needs a Mac with macOS 26 or later,
  Apple Intelligence switched on, and the Xcode 26 SDK to build it. Without Zig or Xcode the quick set above still runs.

## Part 2: per-platform manual list

The same numbered list for macOS, Windows and Linux (X11 and Wayland), so Phase 2.2 only has to run it. Every item has
an expected result. Where the list says `Cmd+W`, Windows and Linux use their own tables of [config.md](config.md)
(`Ctrl+Shift+W`; tab numbers are `Alt+Shift+1` to `9` there, and the line-editing keys are the shell's own on Windows).
`Option` is `Alt` there and the Option-as-Alt setting exists only on macOS; a layout's third level is `AltGr`, which
Windows reports as `Ctrl` and `Alt` together and which holzWave types as the character, never as a chord (item 7 on a
Swiss or German layout is the test; its second half, `option_as_alt`, is macOS only). Copy and paste are `Ctrl+Shift+C` and `Ctrl+Shift+V` (also `Ctrl+Insert`,
`Shift+Insert`, and `Ctrl+V` on Windows); plain `Ctrl+C` always reaches the program. Where an item says `pgrep`, use
`tasklist` on Windows.

## What to expect

Known limits of this build, so they are not reported as defects:

- While a scroll slides (at most 120 ms) the selection highlight, the search matches and the copy cursor are already at
  their final place, because they are drawn from the core's answer and not moved with the text.
- A link or path that cannot be opened (a refused scheme, a missing path, no opener) gives no visible answer yet.
- The palette matches action titles only, shows no highlight of the matched letters and has no recent-first order.
- Hint labels cover the first 676 targets of a pane in reading order, and a number of 7 to 40 digits counts as a hash.
- `Cmd+C` is a fixed shortcut. A chord the core refused stays in the overrides map of `settings.json` until it is reset.
- The UI scale and the font size are user settings; the macOS web view reports no OS text-size signal (D-25).
- Windows and Linux are written and cross-checked from the Mac and have been run by the owner on their own platforms: Part 4
  is the list the owner runs there, and Part 2 is run there too.
- Where Windows and Linux differ from macOS on purpose, the list is in [design.md](design.md) section 7. In short: a
  native window frame; no directory tracking in `cmd.exe`; PowerShell's integration cannot be switched off; Kitty keyboard
  requests from a Windows program may not reach the engine; no middle-click paste on X11; no pointer tear-off and no
  window position restore under Wayland; the OS text size is read on Windows and GNOME only; emoji need a colour emoji font
  on Linux; the installers and packages are unsigned and the Windows installer is NSIS only (the preview installer is a GNU-ABI build); AppImage portability is what
  the run shows; no Option-as-Alt setting off macOS; `Ctrl+V` pastes on Windows and is not rebindable.
- The key binding overrides in `settings.json` do not travel between platforms ([config.md](config.md)).
- The AI chat and the extras were run only against test servers, scripted providers and a page stub. The wire fixtures of the
  five providers are written from the vendors' documents and are not recordings, so a real stream can differ; rows AI1 and
  AI2 close that, and a difference becomes a new fixture and a rule.
- Hiding secrets from the model is best effort: text of a known key shape is replaced by a marker, a secret in another form can
  still be sent, and the chips show labels, sizes and findings, never the text. A file chip is the file as saved, never the
  unsaved edits of an editor.
- A last-command chip on a fresh pane can show the banner of the shell, and the marks that find a command's output are text
  that a program can print itself, so a program can fake or hide the boundary.
- `Insert at prompt` is refused on the alternate screen (`vim`, `less`). A command of the agent runs without an operating
  system sandbox, and the undo of a file change is kept in memory only.
- The `^R` binding yields to a tool that binds the key later in your rc file. The macOS system `bash` 3.2 gets no binding and no
  marks.
- Named pipes on Windows have no read timeouts, so a client that stalls while it sends a `wsh ai` request holds its slot
  until it closes (the sockets of macOS and Linux have them).
- The system monitor over SSH covers Linux hosts; another system is shown as not supported, and an unknown host key is never
  learned by it. Commands typed on other hosts are not recorded in the history, and the history is not synced.
- Provider keys are not available on mobile yet, so the chat refuses to send there.
- The title-bar buttons are smaller than 44 px in a window of 640 px and narrower ([design.md](design.md) names the exception).
- The Apple model needs macOS 26 or later, Apple Silicon and Apple Intelligence, and building it needs the Xcode 26 SDK; an
  older SDK builds the app without it. Where it is missing it cannot be chosen, and nothing falls back to another provider.
- The upload arrow of the system monitor is drawn in the secondary ink in the app and on the design page; the pictures of
  [design.md](design.md) that show a monitor still draw it in rose until they are rendered again.
